# 自适应重访策略说明

固定周期重访让更新频繁的页面和一年不变的页面占用同样的预算。本模块改为
根据已有观测动态安排重访，目标是**减少重要页面长期陈旧**，而不是提高并发。
全部策略均可解释，不依赖预测模型。

## 1. 观测证据的语义区分

一次抓取只产生五类证据，它们携带的信息量不同，不能互相替代：

| 证据 | 含义 | 对"内容是否变化"的证明范围 |
| --- | --- | --- |
| `304` | 条件请求被源站确认 | 强证据，该 ETag 对应内容在抓取时刻仍有效 |
| `unchanged` | 200 且正文摘要与上次相同 | 只覆盖抓取成功的时刻，不依赖源站 ETag |
| `changed` | 200 且正文摘要变化 | 只能说明变化落在**上一次成功抓取与本次之间** |
| `failure` | 5xx/网络错误等短暂失败 | 不携带任何内容信息，不更新内容时间 |
| `redirect` | 显式重定向 | 身份迁移的唯一合法依据 |

关键约束：**抓到变化的时间不是源修改时间**。真实修改时刻只知道落在两次
成功抓取构成的删失区间（censored interval）内，因此系统从不记录"修改时刻"，
只记录区间证据。区间内部夹着失败或无摘要的旧访问（`legacy`）时，该区间
无法闭合，直接作废，不会被当成"无变化"。

## 2. 变化率估计（`observations.py`）

假设页面变化服从泊松过程，变化率 lambda（次/天）由删失区间做极大似然估计：

- "区间内有变化"的区间贡献泊松区间似然 `1 - exp(-lambda * span)`；
- "区间内零变化"的区间贡献 `exp(-lambda * span)`；
- 叠加弱 Gamma 先验（均值约每 30 天一次）解决无历史冷启动，暴露时间越长
  先验影响越小；
- 长期无变化时估计回落到速率下限，不归零。

估计结果同时返回依据（先验/无变化/极大似然）、暴露天数和区间计数，
输出中可以直接看到每个数字的来源。当前内容已陈旧的概率为
`1 - exp(-lambda * 距上次成功抓取的时间)`。

## 3. 重访打分（`planner.py`）

每个候选地址的优先级是可解释的加法模型，由五个分量组成：

1. **截止压力 urgency**：按业务可接受陈旧时长 `max_staleness` 归一化，
   越接近截止时间越高，逾期后封顶为 2，防止单一逾期页面霸占全部预算；
2. **变化风险 change_risk**：上一节算出的"副本已陈旧"概率；
3. **探索 explore**：没有任何内容证据的新地址取 1，取得基线后归零；
4. **饥饿 starvation**：按页面**自身**的可接受陈旧时长归一化，从
   `first_seen`（或上次取得内容）起线性爬升到 1；连续失败不会缓解饥饿；
5. **业务重要度 importance**：参与排序时按 10 封顶，避免极端重要度差距
   让冷门地址永久饿死。

防饿死强保底：饥饿打满（等待超过自身两个陈旧时长窗口）时叠加独立的
`STARVATION_GUARANTEE` 分量，其值高于任何常规组合的上限。因此**任何地址
在有界窗口内必然赢得一次预算**；窗口未满前该分量为 0，不干扰常态排序。

## 4. 失败处理：指数退避与截止时间的取舍

- 连续失败按 `1, 2, 4, 4, ...` 虚拟天指数退避，避免失败页面刷屏挤占预算；
- 短暂失败**不刷新内容时间**，副本陈旧判断仍以上次成功抓取为准；
- 若退避结束时间会突破业务截止时间（且该地址曾成功取得过内容），允许
  提前重试，理由会写入决策记录；从未成功过的地址不享受此豁免，按退避
  节奏探索；
- 同一地址每个虚拟日最多访问一次（提前重试豁免除外）。

## 5. 预算记账：已发请求不算两遍

- 预算在**签发访问凭证（token）时**扣减，而不是拿到结果时；
- 凭证未返回前，同一地址不可再次签发；
- 凭证只能记账一次，重复记账直接报错；
- 访问最终没有发出时用 `release` 归还预算；已记账的请求不退款
  （请求确实发出了）；
- 新的抓取结果到达后，未执行的重访会按最新证据重新排序，已发出的请求
  不受影响。

## 6. 地址改版、合并与退休的身份规则

历史继承只接受**显式永久重定向**这一种证据（`migrate_identity`）：

- 永久重定向：旧地址标记退休，全部观测以 `origin` 标注后继承到目标地址，
  变化率估计在合并后的时间线上重新计算；目标已存在时证据按时间归并；
- 临时重定向：只登记一条 `redirect` 观测，身份不迁移；
- **正文摘要相同绝不合并历史**：两个 URL 即使内容字节完全一致，仍是
  独立页面、独立估计、独立预算；系统不提供按摘要合并身份的入口；
- 退休地址不再参与计划，审计报告中单独标注去向。

## 7. 未满足目标的审计

`unmet_targets` 明确列出当前没有资源满足的新鲜度目标：从未取得内容的
页面、已超出可接受陈旧时长的页面，按业务影响排序。预算不足时不是静默
丢弃，而是每天输出缺口，演练结束后再用来源真实改版时刻计算发现延迟。
